# VyonEx

Kotlin Multiplatform library (JVM, iOS) that turns a YouTube video ID into directly playable
audio or video URLs plus the headers needed to fetch them, and reads the video's metadata.
Apache-2.0.

```kotlin
val vyonEx = VyonEx(host)          // host: your VyonExHost
vyonEx.init()                      // iOS: initialize(); warms up ~2 s later in the background
val stream = vyonEx.extract("dQw4w9WgXcQ", maxKbps = 160)
// stream.url + stream.headers -> ranged GET; on HTTP 403 call vyonEx.onRefused(stream.url)

val video = vyonEx.extractVideo("dQw4w9WgXcQ", maxHeight = 1080)
// video.url is video only; play video.audio alongside it. video.audio == null: a combined format.

val ref = vyonEx.parse("https://music.youtube.com/playlist?list=OLAK5uy_…")   // no network
// VyonExRef.Video(videoId, playlistId, startSeconds), Playlist, Album (MPREb_…) or Mix (RD…); null otherwise

val info = vyonEx.metadata("dQw4w9WgXcQ")
// title, author, channel, duration, views, likes, full description, keywords, category,
// publish/upload dates, thumbnails, live status, private/unlisted/family-safe flags, countries, captions
// and, for YouTube Music uploads, info.music: track, artists, album, release year
```

Android apps use the same API as the JVM (`VyonExHost` with your `OkHttpClient` and, for the player
cache, `context.filesDir`). The library needs `minSdk` 26 and an app compiled against API 37 or
newer, which OkHttp 5.5 requires.

Downloads (every quality YouTube offers, DRM-free formats only):

```kotlin
val formats = vyonEx.formats("dQw4w9WgXcQ")              // all audio and video formats of one client
val best = formats!!.formats.filter { it.hasVideo }.maxBy { it.height ?: 0 }
file.outputStream().use { out -> vyonEx.download(best, formats.headers, { out.write(it) }) }
// 10 MiB ranged requests; pass from = bytes already written to resume.

// Above 360p, video and audio are separate formats. One file, on Android, without re-encoding:
// Android 8 and 9 cannot write Opus into WebM, so they merge MP4 (up to 1080p); choose before downloading.
val container = if (VyonExMerge.supports(VyonExContainer.WEBM)) VyonExContainer.WEBM else VyonExContainer.MP4
val pair = vyonEx.mergePair(formats, maxHeight = 2160, container = container)!!  // WEBM: VP9 + Opus
// (VyonExContainer.MP4: H.264 + AAC, which YouTube offers up to 1080p.) Download pair.video and
// pair.audio into two files as above, then:
VyonExMerge.merge(videoFile, audioFile, outputFile, pair.container)  // needs room for both inputs again
// The same pair from shared (common) code, where VyonEx itself is not available:
val samePair = formats.mergePair(maxHeight = 2160, container = container)

// Audio alone: YouTube's fragmented MP4 and WebM become a plain .m4a (AAC) or an Ogg .opus (Opus, Android 10+).
VyonExMerge.remuxAudio(audioFile, outputFile)
```

Captions and chapters:

```kotlin
val track = vyonEx.metadata("dQw4w9WgXcQ")!!.captions.first()  // languageCode, name, autoGenerated, isTranslatable
val vtt = vyonEx.captionText(track, VyonExCaptionFormat.VTT, translateTo = "de")  // or SRT, TTML, JSON3, SRV1-3
val chapters = vyonEx.chapters("dQw4w9WgXcQ")  // title, startSeconds, endSeconds; empty when there are none
vyonEx.preferAudioLanguage("es-US")  // dubbed videos: that track (see metadata.audioTracks); null keeps the original
```

Channels (logged out):

```kotlin
val channel = vyonEx.channel("UCuAXFkgsw1L7xaCfnd5JJOw")  // title, handle, description, avatars, banners, tabs
val videos = vyonEx.channelTab(channel!!.channelId, VyonExChannelTab.VIDEOS)  // also SHORTS, LIVE, PLAYLISTS
val more = videos.continuation?.let { vyonEx.channelTabMore(it) }
```

Comments (public, logged out):

```kotlin
val page = vyonEx.comments("dQw4w9WgXcQ")  // top first; newestFirst = true for the newest
page.comments.forEach { println("${it.authorName}: ${it.text} (${it.likeCount} likes, ${it.replyCount} replies)") }
val replies = page.comments.first().repliesContinuation?.let { vyonEx.commentsMore(it) }
val next = page.continuation?.let { vyonEx.commentsMore(it) }
```

Live streams (and any video whose client offers one) come as an HLS or DASH manifest, which players read themselves:

```kotlin
val manifest = vyonEx.manifest("jfKfPfyJRdk")  // kind HLS or DASH, url, headers, isLive
// ExoPlayer: HlsMediaSource / DashMediaSource with manifest.headers; AVPlayer: HLS.
```

Playlists (public ones; no cookie is sent):

```kotlin
val playlist = vyonEx.playlist("PLsyOSbh5bs16vubvKePAQ1x3PhKavfBIl")  // title, owner, first ~100 videos
var page = playlist!!.firstPage
while (page.continuation != null) page = vyonEx.playlistMore(page.continuation!!)  // the next ~100
```

YouTube Music albums and artists (links from `parse`: `VyonExRef.Album`, `VyonExRef.Channel`):

```kotlin
val album = vyonEx.album("MPREb_gTAcphH99wE")    // title, artist, year, cover, tracks; playlistId for the same tracks
val artist = vyonEx.artist("UCuAXFkgsw1L7xaCfnd5JJOw")
// Every song by the artist: artist.songsPlaylistId with playlist/playlistMore. Albums and singles: artist.releases.
```

Mixes and recommendations (what YouTube shows next to a video, logged out):

```kotlin
val mix = vyonEx.mix("RDdQw4w9WgXcQ")                 // a video's mix starts with that video
val more = vyonEx.mixMore(mix!!.firstPage.continuation!!)  // mixes go on; continuation is null once nothing is new
val related = vyonEx.related("dQw4w9WgXcQ")           // then relatedMore(related.continuation!!)
```

Search (logged out). Each result says what it opens (`VIDEO`, `PLAYLIST`, `ALBUM`, `ARTIST`, `CHANNEL`) and carries
the ID for `extract`, `playlist`, `album`, `artist` or `channel`:

```kotlin
val videos = vyonEx.search("rick astley")                  // YouTube: videos, playlists, channels; searchMore for more
val shorts = videos.shorts                                 // the Shorts YouTube puts in grids beside the results
val channels = vyonEx.search("rick astley", VyonExSearchType.CHANNELS)
val longest = videos.filters.first { it.group == "Duration" }  // YouTube's own filters, in the session's language
val filtered = vyonEx.search("rick astley", longest)       // with that filter, and any already applied
val ideas = vyonEx.suggestions("rick ast")                 // what YouTube's search box suggests
val music = vyonEx.searchMusic("never gonna give you up")   // YouTube Music top results: songs, albums, artists…
```

SoundCloud's public tracks and sets (logged out, as yt-dlp reads them), on the same host and network client. Encrypted
(DRM) streams are not played: a track that only has those says so with `hasDrm` and has no transcodings.

```kotlin
val track = vyonEx.soundCloud.track("https://soundcloud.com/ethmusic/lostin-powers-she-so-heavy")
val stream = vyonEx.soundCloud.stream(track!!.transcodings.first())  // a fresh signed URL: HLS or one file
vyonEx.soundCloud.download(track.transcodings.first(), sink) { done -> }  // one file; HLS segments joined (.m4a)
val set = vyonEx.soundCloud.playlist("https://soundcloud.com/the-concept-band/sets/the-royal-concept-ep")
```

iOS apps use the same library through `VyonEx.xcframework`:

```swift
import VyonEx

let vyonEx = VyonEx(host: myHost)      // myHost: VyonExHost
vyonEx.initialize()
let video = try await vyonEx.extractVideo(videoId: "dQw4w9WgXcQ", maxHeight: 1080, skipClients: [], requireAvc: true)
let info = try await vyonEx.metadata(videoId: "dQw4w9WgXcQ")   // info?.description_ is the description
```

Swift sees no Kotlin default arguments, so it passes every parameter. A `suspend` function that returns
`Long` (`download`) returns a boxed `KotlinLong` in Swift. Kotlin/Native renames
`description` to `description_` because `NSObject` already has a `description`.

## How it works

1. Reads `host.session()` (cookie, visitor data, `gl`, `hl`) on every call.
2. Asks the player API with one client identity after another (`Clients.kt`), in yt-dlp's current
   default order: logged out `TV_SAMSUNG` (TVHTML5), `VISIONOS`, then `WEB` (only with a PO token
   from `host.tokenProvider`); logged in `WEB_EMBEDDED`, `TV_SAMSUNG`, `WEB` (no `VISIONOS`, which
   takes no cookies). Then two more TV clients that need no PO token, `TV` and `TV_DOWNGRADED`. A
   client refused three times in a row, across videos, is tried last for 30 minutes.
3. Decodes signature and `n` by running the player script's own functions in QuickJS, through
   yt-dlp's EJS solver (vendored in `ejs/`). The prepared player is cached per player version
   (JVM: `filesDir/vyonex-players`, three newest; iOS: memory).
4. Audio: picks a format (`requireM4a`, `maxKbps <= 64`, or AUTO). Video: the tallest format up to
   `maxHeight` (the smallest if none fits), then frame rate, then H.264 over VP9 over AV1, then
   bitrate; `requireAvc` keeps only H.264 video and AAC audio (what AVPlayer plays). Video-only
   formats come with the best audio up to 160 kbps. On a video with dubbed audio, every choice is
   made from the original track's formats (as yt-dlp ranks them).
5. Allows only `https://*.googlevideo.com|youtube.com/videoplayback` URLs (manifests:
   `https://*.googlevideo.com/api/manifest/…`), never SABR, and
   checks every returned URL answers a one-byte ranged GET with the returned headers: only a 206
   for that byte counts (not a 200, which ignored the range, nor an HTML, JSON or text page), and
   the answer's body is never read. A refused identity is excluded for 10 minutes and the next one
   is tried.
6. iOS `extract` falls back to the watch page; `audioCandidates` lists the watch page's audio.
7. `metadata` asks `WEB` (which adds the microformat: likes, category, dates, countries), then
   `VISIONOS`; it returns null when neither reports video details.
8. When YouTube refuses the video to every client, `extract`, `extractVideo` and `formats` throw
   `VyonExUnplayableException`: `reason` (age-restricted, sign-in required, unavailable, upcoming,
   country-blocked or other, sorted as yt-dlp does) and `youtubeReason`, YouTube's own message.
   Swift gets it as the `NSError`'s `kotlinException`.
9. `playlist` and `playlistMore` ask the logged-out WEB `browse` endpoint and read each video
   (`lockupViewModel`) as yt-dlp does: title, channel, duration, thumbnails.
10. `album` and `artist` ask YouTube Music's own web client (`WEB_REMIX`) the same way. Shelves on
    an artist page are told apart by what they link to, not by their localized titles.
11. `mix`, `mixMore`, `related` and `relatedMore` ask the logged-out WEB `next` (watch-next)
    endpoint: the mix panel's videos and the related videos beside the player.
12. `search` asks the WEB `search` endpoint and `searchMusic` YouTube Music's; results are classified
    by what they link to, never by localized labels such as "Song" or "Album". Filters are the params
    YouTube's own response offers; `suggestions` asks the host YouTube's search box asks.

## The app (in progress)

The Android app lives in this repository, on top of the library. `app-core/` is its shared logic (Kotlin
Multiplatform, so an iOS app can reuse it): the play queue and the playback controller. `android-app/` is the
Android shell (Compose, Media3): paste or share a YouTube or YouTube Music link (a video, playlist, album, mix
or artist), see its tracks, and play them in the background with the system's media notification. Each track,
or the whole page, can be downloaded: audio (AAC or Opus, every bitrate YouTube offers) or video (every height,
merged into one MP4 or WebM file), into Music/VyonEx and Movies/VyonEx, with progress in a notification.
SoundCloud links (a track or a set) open, play and download too: the best audio that is not encrypted (DRM), saved
as `.m4a`, `.mp3` or `.opus`; a track SoundCloud only offers encrypted says so. Anything typed that is not a link
is searched on YouTube, with YouTube's suggestions while typing: a video plays (and the videos after it in the
results), a playlist, album, artist or channel opens as a page with a way back to the results. No player screen yet.

```kotlin
val playback = Playback(source, scope, nowSeconds)  // source: VyonEx behind StreamSource
playback.play(tracks)       // looks up the first track's stream, then the next one's ahead
playback.state              // Idle, Loading, Ready(track, stream) or Failed(track, failure, YouTube's reason)
                            // each Ready, a repeat too, is a new value: start the stream from the beginning
playback.ended()            // from the platform player; follows repeat (off, all, one)
playback.refused(url)       // the player got HTTP 403: VyonEx is told, and the track is looked up once more
```

To try the app (Android 8.0 or newer), take `vyonex-android-debug` from a CI run's Artifacts. It is a debug
build signed with that run's throwaway key, so uninstall the previous one before installing a newer one.

## Build and test

Gradle 9.8.2 (wrapper), Kotlin 2.4.21, JDK 27 toolchain, JVM target 26.

```sh
./gradlew jvmTest jvmJar                      # any OS (library and app-core)
./gradlew assembleAndroidMain                 # Android AAR; needs ANDROID_HOME (an Android SDK)
./gradlew :android-app:assembleDebug          # the app's debug APK, in android-app/build/outputs/apk/debug/
./gradlew iosSimulatorArm64Test assembleVyonExReleaseXCFramework   # macOS
VYONEX_LIVE=1 ./gradlew jvmTest --tests com.vyonex.LiveTest --rerun   # live, opt-in
VYONEX_LIVE=1 VYONEX_LIVE_IDS=id1,id2 ./gradlew jvmTest --tests com.vyonex.LiveTest --rerun   # also surveys these videos
```

The survey prints one line per video (profile, itag, HTTP code, or YouTube's reason; never URLs)
and fails only if a returned URL does not answer.

On the JVM the prepared player is cached under `filesDir` only while `configStore.enabled` is true.
`close()` stops background work and frees the loaded player when the host is done with VyonEx.

Offline tests read the captured responses in `fixtures/` (see `fixtures/README.md`).
`apicheck/ApiCheck.swift` is type-checked against the XCFramework in CI.

## Files

- `src/commonMain`: public API and the engine; `src/jvmMain`, `src/iosMain`: `VyonEx`, `VyonExHost`, transport, disk cache.
- `ejs/`: the vendored yt-dlp/ejs solver, compiled into the library.
- `app-core/`: the app's shared logic (queue, playback controller); `android-app/`: the Android app.
- `PROVENANCE.md`: every source used. `QUESTIONS.md`: open questions. `NOTICE`: third-party notices.
