# eXcor feature matrix

This matrix describes the active clean-room Kotlin sources under `modules/cleanroom/` and the separate Swift package under `modules/platforms/swift/`. Preserved implementation folders are excluded. CI (`.github/workflows/ci.yml`) runs the offline tests and builds on Linux, Windows and macOS for every push and pull request; live checks against YouTube and the music providers are opt-in (`EXCOR_LIVE=1`) and are recorded with their date and the network they ran from. `Supported and verified` means the behavior has a public API, relevant tests, and passing CI for the stated target; it does not by itself mean production-ready.

| Capability | Kotlin KMP status | eXcorKit status | Evidence or gap |
|---|---|---|---|
| Resolve audio from a YouTube video ID | Supported; live full-decode verified 2026-11-12 | Supported and verified on CI targets | `Excor.extract` / `ExcorKit.extract`; offline tests in CI on every target. On one signed-out Windows home-network video, the paired adapter downloaded and decoded the 3,507,483-byte Opus stream and passed both offset range probes in 3/3 cold attempts. Both adapters also completed 3/3 cold and warm full-decode/range samples under Temurin JDK 17.0.20.1; this is one video/network, not broad reliability proof. See the [JDK 17 report](../modules/samples/black-box-comparison/results/owner-home-2026-11-13-jdk17-direct-audio.md). |
| List a video's downloadable formats | Supported; live-verified 2026-11-03 | Unsupported | `Excor.formats(videoId)` returns every whole-file format of the first client whose response plays (`ExcorFormatList`: itag, MIME type, codec, size, frame rate, bitrate, length, byte ranges; one set of headers). `LivePlaybackTest.formatListIsRangeReadable`: 27 formats from VISIONOS, 144p to 2160p plus audio, every one answering a range read. `EngineStateTest.formatListHasEveryWholeFileFormatAfterOneProbe` |
| Resolve video from a YouTube video ID (video track plus matching audio) | Supported; live-verified 2026-11-03 and rerun 2026-11-12 | Unsupported | `Excor.extractVideo(videoId, maxHeight, codecs, maxAudioKbps)` returns an `ExcorVideoTrack` (size, frame rate, codec, byte ranges for DASH) and the audio to play with it, both probed. `LivePlaybackTest.extractedVideoAndAudioDecodeAndMux`: 480p (854x480, 14.1 MB) and 1080p (1920x1080, 80.9 MB) H.264 from VISIONOS, downloaded in 4 MiB range reads, muxed with M4A audio by FFmpeg without re-encoding and fully decoded (213.09 s), mid-file range read correct. A fresh 2026-11-12 480p run also muxed and decoded fully (213.089 s). Only for videos YouTube serves to the test network; most are bot-checked there |
| HLS manifest handoff | Experimental; synthetic tests, live playback unverified | Unsupported | `Excor.extractHls(videoId)` returns a host-player manifest after HTTPS GoogleVideo URL/path validation, bounded `#EXTM3U` response check and validated redirect handling. Host players fetch child playlists and segments. The SDK does not proxy or validate those child requests. |
| Apple/iTunes track, album, and artist metadata | Experimental Kotlin adapter; offline tests and cross-target CI pass | Unsupported | Synthetic search, lookup, album-track, and artist-album fixtures; live API behavior is unverified, and this uses iTunes Search/Lookup rather than the full Apple Music API |
| Deezer catalog metadata (`Excor.music`) | Supported; live-verified 2026-11-01 (keyless public API) | Unsupported | Track, album, artist and playlist reads, search, ISRC and UPC lookup, charts, genres, related artists and playlist sync all pass `LiveMusicTest`. The user library is offline-tested only, and new Deezer app registration is reportedly closed. |
| Spotify catalog metadata | Experimental Kotlin adapter; offline tests and cross-target CI pass | Unsupported | Host supplies OAuth access tokens; synthetic fixture tests cover search, lookup, album tracks, artist albums, pagination, and auth errors; current terms and live access remain unverified |
| YouTube Music catalog metadata | Supported; songs and albums live-verified 2026-11-03; one full artist album-shelf pagination flow live-verified 2026-11-13; cloud access remains blocked | Unsupported | YouTube Music is read through InnerTube (`Excor.musicSearch`, `musicArtist`, `musicPlaylist`, `musicRadio`). `LiveVideoInfoTest.youTubeMusicArtistAlbumShelfOpensFullDiscography` confirms one artist's typed, unique album pages through the end of its continuation. Cross-artist/network coverage and Singles & EPs remain unverified. |
| Cross-provider catalog API | Experimental Kotlin models and capability surface; offline tests and cross-target CI pass | Unsupported | Search, URL lookup, album tracks, and artist albums are wired for Apple and Spotify |
| Unified music API (`Excor.music`) for Spotify, Apple Music and Deezer | Implemented; offline tests; Deezer and iTunes live-verified | Unsupported | `docs/MUSIC_API.md`. Spotify Web API and Apple Music API calls are tested with synthetic responses only, because no credentials were available. |
| Cross-provider matching and enrichment | Implemented; offline tests; Deezer→Apple live match verified | Unsupported | `MatchingTest` covers live, remaster, clean/explicit, cover, remix and duration cases. |
| Incremental playlist and library sync | Implemented; offline tests; Deezer playlist live-verified | Unsupported | Snapshot short-circuit, resume, retries, moves and duplicates (`SyncAuthTest`). |
| Audio formats, quality declarations and format selection | Implemented; offline tests | Unsupported | RFC 6381 parsing and Apple `audioVariants` traits. Spotify and Deezer declare no per-track quality. |
| DRM detection and playback decisions | Implemented; offline tests | Unsupported | HLS and DASH protection parsing. eXcor ships no protected-playback adapter, and none has been tested on a device. |
| OAuth (Spotify PKCE), token manager, SHA-256 | Implemented; offline tests with standard vectors | Unsupported | FIPS 180-4 and RFC 7636 known answers. |
| Select M4A, low-bitrate, or automatic audio | Supported and verified | Supported and verified | Kotlin `SelectionTest`; Swift selection tests |
| Decode player signature and `n` challenges | Implemented; successful transformed-media playback unverified | Implemented; successful ciphered playback unverified | Synthetic tests cover signature-only, direct-URL `n`, and malformed-`n` eligibility. Twelve signed-out public watch-page responses exposed neither `signatureCipher` nor a direct-URL `n` challenge, so the verifier skipped before fetching player JavaScript. The TVHTML5 playback check was refused before extraction. See the [expanded recheck](../modules/samples/black-box-comparison/results/owner-home-2026-11-13-cipher-recheck.md) and earlier [TVHTML5 attempt](../modules/samples/black-box-comparison/results/owner-home-2026-11-13-tvhtml5-only.md). |
| Restrict returned playback URLs | Supported and verified | Supported and verified | URL-policy tests in each package |
| Host-owned session and PO-token integration | Interface implemented; provider behavior varies | Interface implemented; provider behavior varies | Host supplies session/token service; eXcor does not mint tokens |
| Catalog search and pagination | Experimental for Apple/iTunes and Spotify | Unsupported | Provider-bound offset tokens; synthetic pagination tests only |
| YouTube video metadata lookup | Supported; live-verified 2026-11-01 | Unsupported | `Excor.videoInfo(videoId)` returns title, channel, handle, duration, views, likes, keywords, category, dates, countries, flags and playability from the InnerTube player response. YouTube returns this metadata even when it withholds streams. `asMusicTrack()` passes the video to cross-provider matching (verified live against Deezer). When YouTube's bot check withholds the details from the player response, `videoInfo` reads them from the watch page (`fromWatchPage`: title, channel, views, description, displayed date; no duration). Live-verified 2026-11-02. |
| YouTube search | Supported; live-verified 2026-11-01 | Unsupported | `Excor.search(query, continuation, filterParams)` uses InnerTube search and returns videos (duration, views, channel, official-artist flag, live), Shorts, channels (handle, subscriber text) and playlists and mixes, with continuation pages. Each page lists YouTube's own filter dialog (type, duration, upload date, features, sort) with the params for each option; passing one filters the search, and continuations keep the filter. `Excor.findOnYouTube(track)` finds a Spotify, Apple Music or Deezer track on YouTube: one search, each video scored by the cross-provider matcher (live-verified 2026-11-02 from a Deezer track). |
| YouTube playlists | Supported; live-verified 2026-11-01 | Unsupported | `Excor.playlist(playlistId, continuation)` uses InnerTube browse and returns title, description, owner and channel, video count, views, last-updated text, and videos (duration, channel, views and published text, thumbnails) with continuation pages. YouTube omits unavailable videos. Mixes ("RD" playlists), which browse calls unviewable, come from `Excor.mix(videoId, playlistId, index)` through the watch playlist panel: about 25 videos per window, with the video and index to continue from (live-verified 2026-11-02). |
| YouTube channels | Supported; live-verified 2026-11-01 | Unsupported | `Excor.channel(channelId, continuation, tab)` returns title, description, handle, subscriber and video-count texts, keywords, countries, avatars and tabs, plus one tab: Videos (default), Shorts, Live, Playlists or Posts, with continuation pages. Posts give text, published and like texts, and the largest size of each attached image (live-verified 2026-11-02). Tabs are matched by address, so localized titles don't matter. Videos streaming now are marked `isLive` (live-verified on a streaming channel's Live tab). A tab the channel lacks gives an empty list; a tab it has that fails to load gives null rather than an empty list. The first page takes two requests. `Excor.channelAbout(channelId)` reads the About panel (two requests): description, subscriber and video-count texts, total views, join date, country when shown, and the channel's links with each destination taken out of YouTube's redirect (the redirect token is dropped). |
| YouTube related videos and comments | Supported; live-verified 2026-11-01 | Unsupported | `Excor.related(videoId, continuation)` and `Excor.comments(videoId, continuation)` use the InnerTube `next` endpoint. Comments carry author, verified/creator/artist flags, published text, likes text and reply count, in Top order or `newestFirst`, with continuation pages. Replies come through each comment's `repliesContinuation`. `Excor.chapters(videoId)` returns the video's chapters (title and start time, in order) from the same `next` response, one request; empty when the video has none. Live-verified 2026-11-02. `Excor.songs(videoId)` returns the songs YouTube credits in the description's Music section (title, artist, album and its credit lines), one request; `song.asMusicTrack(videoId)` makes one matchable across providers. Live-verified 2026-11-02, including a Deezer match. |
| YouTube search suggestions | Supported; live-verified 2026-11-01 | Unsupported | `Excor.suggestions(query)` uses YouTube's suggestion service in the session's language and region. |
| YouTube transcripts | Not implemented | Not implemented | Checked 2026-11-01: `get_transcript` answers "Precondition check failed" from this environment. eXcor does not work around YouTube's checks, so transcripts stay unimplemented. |
| YouTube hashtag pages | Not implemented | Not implemented | Checked 2026-11-01: `/hashtag/<tag>` answers with YouTube's robot check from this environment, and eXcor does not work around it. |
| YouTube caption track list | Not implemented | Not implemented | Checked 2026-11-02: from this environment the player response is `LOGIN_REQUIRED` or `UNPLAYABLE` and carries no `captions`, so the track list can't be observed or verified here. eXcor does not work around it. |
| YouTube channel Releases tab | Not implemented | Not implemented | Checked 2026-11-02: from this environment the Releases tab answers "No releases available" for every artist tried, matching the hidden YouTube Music catalog below. |
| YouTube Music search, suggestions, artists, playlists, radio | Supported; live-verified 2026-11-02 | Unsupported | `Excor.musicSearch(query, continuation, filterParams)` returns typed items (song, video, episode, artist, album, playlist, profile, podcast), read from YouTube Music's music-video and page types rather than its localized labels, with YouTube Music's own filters and continuations. The top result card is typed the same way: a page it opens (artist, album, playlist) or a video or song it plays, with the video ID and duration (live-verified 2026-11-03). Also `musicSuggestions`, `musicArtist` (description, audience, shelves, radio and shuffle queues), `musicPlaylist` (typed tracks with durations) and `musicRadio` (endless queue windows). |
| YouTube Music songs, albums, singles, discographies | Songs and albums live-verified 2026-11-03; one artist album-discography pagination flow live-verified 2026-11-13; Singles & EPs remain unverified | Unsupported | `LiveVideoInfoTest.youTubeMusicArtistAlbumShelfOpensFullDiscography` resolves Daft Punk from live search, opens its album shelf, follows the `MPAD` grid continuation to completion, and checks typed, unique album browse IDs beyond the artist-page preview. This is one artist/network; it does not establish cross-artist or cross-network coverage. Cloud containers still withhold Songs/Albums results. |
| Preview apps (Android APK, Windows EXE) | Built on the library; in CI | Not applicable | `preview-android`: search, details, audio/video playback (ExoPlayer), experimental HLS manifest playback through Media3 HLS, formats and log; linted and started on API 26 and 36 emulators. One signed-out Android 16 attempt returned UNPLAYABLE before a manifest; successful HLS playback remains unverified and child requests remain host-player-managed. See the [attempt report](../modules/samples/black-box-comparison/results/owner-home-2026-11-13-android-hls-attempt.md). `preview-desktop`: the same browsing flows and direct audio/video playback through the system player, plus saving formats; packaged with jpackage, self-tested on Linux and Windows, started under Xvfb. Checked by hand 2026-11-03 under Xvfb: search (17 results), details, and Play video (720p H.264 plus AAC joined by ffmpeg, 213.09 s, clean decode) |
| Public release readiness | Not ready | Not ready | Owner-run matched playback, full decode, key-driven seek and cipher evidence; source/fixture provenance and license review; API/ABI compatibility and reproducible release builds; and publication authorization remain open |

## Platform verification

The latest recorded six-job CI evidence for the current `main` tree is run [43154435924](https://github.com/bxanedot/eXcor/actions/runs/43154435924), which passed at exact PR head `ffac3a264df4d20a0ad70038c9e024b8ad8e83df` before merge as `5224428f171d7d58f93ce05f84b7306d89cb9d64`. The root workflow covers supported Linux, Windows and macOS targets, including Kotlin checks, Android compilation, iOS simulator/framework work and the native Swift package. This records CI build evidence only; it does not assert fresh local verification or live playback.

No provider is marked release-ready merely because a documented interface or CI check exists. Apple live behavior and Spotify's current terms/access remain unverified; Deezer and YouTube Music remain gated on verified authorized access paths.
