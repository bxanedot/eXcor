# Competitive capability matrix

eXcor is compared on capabilities that are documented or can be observed from outside. Competitor implementation code is not used or copied. Sources are recorded in `PROVENANCE.md`.

**Sources:**
- **InnerTubeX:** public [README](https://github.com/MetrolistGroup/innertubex) and [CHANGELOG.md](https://github.com/MetrolistGroup/innertubex/blob/main/CHANGELOG.md), plus the v0.11.6 [JVM build configuration](https://github.com/MetrolistGroup/innertubex/blob/v0.11.6/build.gradle.kts), checked 2026-11-13. The latest published release is v0.11.6; its README install snippet still pins v0.11.5. The v0.11.6 README documents a source-built JVM playback harness. We ran it at exact release commit `64c7df4d88d27e6964157b3b341f7ec70f88ea6e` for the seek check below.
- **YouTube.js:** public README, [Getting Started](https://ytjs.dev/guide/getting-started), [API docs](https://ytjs.dev/api/), and [npm package metadata](https://www.npmjs.com/package/youtubei.js), checked 2026-11-11. The separate adapter pins MIT-licensed `youtubei.js@18.3.0`, uses direct-URL audio only, and does not execute player JavaScript.
- **NewPipeExtractor:** official README, v0.27.1 release notes and v0.27.1 Javadocs, checked 2026-11-11.

## YouTube.js and NewPipeExtractor

The short READMEs establish platforms and installation. YouTube.js also publishes an extended guide and API docs, while NewPipeExtractor exposes a larger service surface than the short summary below. This table deliberately makes no unsupported claim about their full feature coverage.

| | YouTube.js (documented) | NewPipeExtractor (documented) | eXcor |
|---|---|---|---|
| Runtime | "Node.js, Deno, modern browsers, and more"; JavaScript | Java library for Android and Gradle projects (desugaring below minSdk 33); a "core component of NewPipe" | Kotlin Multiplatform: JVM, Android (minSdk 26), iOS |
| Services | YouTube's InnerTube ("A JavaScript client for YouTube's internal API") | YouTube, SoundCloud, media.ccc.de, Bandcamp, PeerTube | YouTube, YouTube Music; Spotify, Apple Music and Deezer catalogs |
| Installation | npm, Yarn, Deno | JitPack; snapshots as `net.newpipe:extractor` | `maven-publish` to a local repository; CI-verified consumer |

eXcor's per-feature evidence lives in `FEATURE_MATRIX.md` and `EXCOR_ENGINEERING_AUDIT.md`. Public-API feasibility for a four-library benchmark, including version pins, instrumentation points and adapter license boundaries, is recorded in [`BLACK_BOX_COMPARISON_RESEARCH.md`](BLACK_BOX_COMPARISON_RESEARCH.md). The offline report validator and aggregator plus standalone eXcor, InnerTubeX, YouTube.js and NewPipe adapters run in separate processes; `run_matched.py` supplies shared comparison metadata and validates sanitized outputs without making requests in CI. The InnerTubeX adapter pins v0.11.6, YouTube.js uses direct-URL audio only and reports cipher-only cases as unsupported, and NewPipe pins v0.27.1. NewPipe passed all six exact-head CI jobs in run `43102342730`; YouTube.js passed all six in `43105597786`; InnerTubeX passed all six in `43109304794` at exact head `4e4931cf1011fa8ad37acd89319798365593c59d`. The [2026-11-13 shared-pass report](../modules/samples/black-box-comparison/results/owner-home-2026-11-13-adapter-fix-full.md) shows eXcor 0.1.4 and InnerTubeX adapter 0.1.3 passing full 3,507,483-byte audio decode and both HTTP byte-offset probes in 3/3 cold attempts on one signed-out video and Windows home network. First-media-byte p50 was 5,130 ms for eXcor and 1,174 ms for InnerTubeX; decode p50 was 314 ms and 372 ms. The three-sample shared run is diagnostic, its source worktree is uncommitted, and it does not establish broad reliability or player-seek parity. The initial two additional IDs were access differentials, not additional shared passes; see their sanitized reports in `modules/samples/black-box-comparison/results/`. All three IDs used one network. The older [2026-11-12 report](../modules/samples/black-box-comparison/results/owner-home-2026-11-12-range-full.md) and [two-ID recheck](../modules/samples/black-box-comparison/results/owner-home-2026-11-12-classifier-recheck.md) used InnerTubeX adapter 0.1.2 before the JSON serialization fix; their failures are historical, and the second ID was access-blocked for eXcor.
