# Competitive capability matrix

eXcor is compared on capabilities that are documented or can be observed from outside. Competitor implementation code is not used or copied. Sources are recorded in `PROVENANCE.md`.

**Sources:**
- **InnerTubeX:** public [README](https://github.com/MetrolistGroup/innertubex) and [CHANGELOG.md](https://github.com/MetrolistGroup/innertubex/blob/main/CHANGELOG.md), checked 2026-11-11. The changelog's latest entry is v0.11.6 (2026-11-07), while the README install snippet still pins v0.11.5. The README also documents a source-built JVM playback harness with paced audio playback, real backward/forward transport seeks, HLS/direct/SABR profiles, a smoke mode, and sanitized reports. These are requirements-level references; implementation source was not inspected.
- **YouTube.js:** public README, [Getting Started](https://ytjs.dev/guide/getting-started), [API docs](https://ytjs.dev/api/), and [npm package metadata](https://www.npmjs.com/package/youtubei.js), checked 2026-11-11. The separate adapter pins MIT-licensed `youtubei.js@18.3.0`, uses direct-URL audio only, and does not execute player JavaScript.
- **NewPipeExtractor:** official README, v0.27.1 release notes and v0.27.1 Javadocs, checked 2026-11-11.

Where InnerTubeX documents capabilities the active eXcor SDK lacks (DASH manifest playback and SABR/UMP), eXcor has not demonstrated parity. eXcor's HLS manifest handoff is experimental and has no live playback evidence. The direct-audio runner is not yet supported by owner-run seek/decode evidence or a same-machine comparison. eXcor's direct-stream evidence is limited to the cited eligible videos and networks; no apples-to-apples performance comparison exists. Some eXcor catalog features go beyond what the consulted InnerTubeX README explicitly describes; that is not proof InnerTubeX lacks them.

## YouTube.js and NewPipeExtractor

The short READMEs establish platforms and installation. YouTube.js also publishes an extended guide and API docs, while NewPipeExtractor exposes a larger service surface than the short summary below. This table deliberately makes no unsupported claim about their full feature coverage.

| | YouTube.js (documented) | NewPipeExtractor (documented) | eXcor |
|---|---|---|---|
| Runtime | "Node.js, Deno, modern browsers, and more"; JavaScript | Java library for Android and Gradle projects (desugaring below minSdk 33); a "core component of NewPipe" | Kotlin Multiplatform: JVM, Android (minSdk 26), iOS |
| Services | YouTube's InnerTube ("A JavaScript client for YouTube's internal API") | YouTube, SoundCloud, media.ccc.de, Bandcamp, PeerTube | YouTube, YouTube Music; Spotify, Apple Music and Deezer catalogs |
| Installation | npm, Yarn, Deno | JitPack; snapshots as `net.newpipe:extractor` | `maven-publish` to a local repository; CI-verified consumer |

eXcor's per-feature evidence lives in `FEATURE_MATRIX.md` and `EXCOR_ENGINEERING_AUDIT.md`. Public-API feasibility for a four-library benchmark, including version pins, instrumentation points and adapter license boundaries, is recorded in [`BLACK_BOX_COMPARISON_RESEARCH.md`](BLACK_BOX_COMPARISON_RESEARCH.md). The offline report validator and aggregator plus standalone eXcor, YouTube.js, and NewPipe JVM adapters are implemented in separate processes. The YouTube.js adapter uses direct-URL audio only and reports cipher-only cases as unsupported; the NewPipe adapter pins v0.27.1. NewPipe exact-head CI passed all six jobs in run `43102342730`; the current YouTube.js hardening revision and InnerTubeX adapter still need exact-head CI review. Full decode and backward/forward seek measurements and reproducible matched runs remain outstanding. The changelog documents tokenless SABR audio starts with deferred token attachment, QuackJS updates and iOS cipher reliability fixes; these are documented capabilities, not black-box playback verification. The README install snippet still names v0.11.5 while the changelog's latest entry is v0.11.6. No latency, success-rate or stream-parity superiority claim is justified.
